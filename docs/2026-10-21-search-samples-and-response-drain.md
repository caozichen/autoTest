## 脚本改动

- **创建完整表单（含内地入口）**：返回独立回读的分享渠道，写入 `FORM_CONTRACT.settings.channel`，并核对保存、发布后的渠道配置。
- **填写指定表单**：校验渠道链接的环境、表单 ID、渠道 code，使用真实渠道链接填写；校验实际请求 `answers.channel`，不修改应用提交请求。完成首次提交及满额验证后，在独立后台登录上下文通过详情 UI 为同一答卷添加唯一备注；只允许一次备注写入，再刷新、独立回读渠道及备注。
- **检查提报列表**：读取 `SUBMISSION_ASSERTIONS.searchSamples`，要求准备的渠道 code 和完整备注真实显示；分别检查完整值命中、中间片段命中、无关值排除、清空条件恢复。字段统计仍按检索字段数计数。显示值缺失记录失败，并使用前序独立回读确认的样本继续检索其余场景，防止单个显示缺陷遮住后续覆盖。没有预期样本的独立运行继续支持合法空值反查；存在预期样本时不允许退化成空值反查。
- **检查并编辑提报信息**：接受新增样本契约，在编辑前、保存并刷新后独立回读，确认渠道、备注不丢失。题目答案快照排除右侧侧栏，避免标签切换或系统更新时间引起误报；仍展开核对矩阵，保留附件、图片和 API 原始答案的不变性检查。
- **设置校验表单多语言翻译**：在分享弹窗、无认证短链页、语言预览、布局夹具的每个关闭位置，以及正常成功结束前，等待本页必要接口正文和资源完成。公共字典始终保留；流、AI 后台状态轮询、遥测及被导航替换的旧文档请求按范围排除。每次必要响应等待 45 秒，按环境缩放；超时、损坏 JSON、失败业务码均失败。

## 实跑确认的产品缺陷：渠道已保存，列表仍为空

可直接从用户操作复现，不需要故障注入：创建分享渠道，打开该渠道的链接并提交答卷；进入答卷详情，基本信息的渠道能看到本次 code；返回提报列表，在字段设置中勾选渠道，目标行却显示 `-`。

测试表单 `4ZMom1`、公开答卷 `q9BNbk` 已验证：

- 详情接口 `/api/be/form/4ZMom1/submission/q9BNbk` 的 `items[channel].value[0].answer` 为 `4G01Ld_jbiEXYtuzG-G`。
- 列表接口 `/api/be/form/4ZMom1/submission` 的同一答卷 `answers` 中没有 `channel`，返回的 `items` 中也没有渠道定义。
- 渠道完整值和中间片段仍能筛出目标答卷；无关值能排除，清空后能恢复。渠道已经写入及建立检索索引，问题发生在列表组装与展示。
- 备注已保存，并在详情刷新、列表展示和完整值/模糊/排除/恢复查询中通过。专项列表检查执行 20/20 个字段，仅渠道显示这一条失败。

源码链路：后端 `app/Services/Form/Submission/FormSubmissionManageService.php` 的 `getItemsForSubmissionList()` 把 `Registry::systemItemDefinitions()` 中所有键加入排除集，其中包括 `channel`。随后 `FormAnswerText::hydrateAnswersByLatestPublishedRevision()` 只按过滤后的 `$form->items` 组装答案，因此渠道不会进入列表响应。前端 `reply-tab.vue` 允许从表单详情生成渠道列，但该行的 `answers` 没有渠道，`dyn_channel` 最后显示 `-`。

建议产品修复明确支持的系统字段（至少渠道）的列表序列化，使渠道定义、答案和前端列保持一致；不宜无差别公开所有隐藏系统字段。本次保留失败断言，未改动产品仓库。独立接口证据在 `channel-list-evidence.json`，专项列表结果在 `live-downstream-check.json`。
